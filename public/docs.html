Quickstart

Fastest path from zero to a model reply:

  • Just chat: open /chat and type. Guests get 10 messages/hour.
  • Account: sign up with your email, enter the 6-digit code we send you.
  • API key: dashboard → New key → copy it (shown once) → call POST /v1/chat/completions.
  -H "Authorization: Bearer lq_your_key" \
  -H "Content-Type: application/json" \
  -d '{"model":"lattice-quark-1.5b","messages":[{"role":"user","content":"Hello!"}]}'

Accounts

Sign up with an email and a password (8+ characters). We email you a 6-digit verification code - it expires in 15 minutes and you get 5 tries. Ask for a new one any time from the auth page or the dashboard banner. API key creation requires a verified email; everything else works unverified.

Accounts are free. There's no paid tier and no plan to add one.

Web chat

The chat talks to both models - switch between Quark and Spark in the top bar, any time, even mid-conversation. Chats are stored in your browser's local storage (nothing leaves your device for history), and you can run multiple conversations from the sidebar.

  • Guests: 2 messages/minute, 10/hour per IP.
  • Signed in: soft per-minute limits, generous for normal use.

If a reply takes a while after the site's been idle, the models are warming back up on the GPU - the first request can take a minute, then it's fast.

API keys

Create up to 5 active keys in the dashboard. Give each a name ("opencode", "my-bot") so you know what to revoke later. Keys:

  • start with lq_, shown exactly once - save it immediately;
  • are stored hashed, so we can't recover a lost key (just make a new one);
  • can be revoked instantly from the dashboard;
  • share your account's rate limits (50/min, 1,000/day) - usage is tracked per key.

The dashboard also shows your usage: requests per day, characters generated, per-key breakdown, last 30 days.

API reference

Base URL + auth

https://lattice.mebbo.cloud/v1
Authorization: Bearer lq_your_key

GET /v1/models

Lists the available models. Auth required.

POST /v1/chat/completions

OpenAI-compatible. Body: model, messages (array of {role, content} - system messages are honored). Optional: stream.

{
  "model": "lattice-quark-1.5b",
  "messages": [
    {"role": "system", "content": "You are concise."},
    {"role": "user", "content": "Hello!"}
  ]
}

Response: standard chat.completion JSON with choices[0].message.content. stream: true returns the full reply as a single SSE chunk - real token streaming isn't supported by the backend yet.

Notes

  • Conversation history is trimmed to the last few turns server-side (2048-token context window).
  • CORS is open, so browser apps can call the API directly (mind your key exposure).
  • Cold starts: after idle, the first call reloads the models - up to a minute or two. Retry and it's fast.

SDKs & tools

Python (OpenAI SDK)

from openai import OpenAI

client = OpenAI(
    base_url="https://lattice.mebbo.cloud/v1",
    api_key="lq_your_key",
)

r = client.chat.completions.create(
    model="lattice-quark-1.5b",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(r.choices[0].message.content)

opencode / Cline / any OpenAI-compatible client

Set the base URL to https://lattice.mebbo.cloud/v1, the API key to your lq_ key, and the model to lattice-quark-1.5b or lattice-spark-1.5b.

Rate limits

ScopeLimit
API keys50 requests/minute · 1,000 requests/day (per account, shared across your keys - 5 active keys max)
Signed-in web chatsoft per-minute limits
Guest web chat2 messages/minute · 10/hour per IP

Over a limit → HTTP 429 with a plain-English message. One shared GPU serves everyone - the limits keep it fair.

Errors

The API uses the OpenAI error shape: {"error": {"message": "...", "type": "..."}}.

TypeMeaning
auth_errorMissing, wrong, or revoked key
rate_limit_errorMinute or daily limit hit - back off
invalid_request_errorBad JSON, no messages, unknown model
upstream_errorModel warming or unreachable - retry in a few seconds

Data & privacy

  • We store your email, hashed password, hashed API keys, and aggregate usage (counts, latency, model) for the dashboard and abuse controls.
  • Web chat history lives in your browser, not on our servers.
  • Guest chats are rate-limited by IP and not tied to an identity.
  • Don't paste secrets into prompts - treat Lattice like any public model.
  • Abuse gets keys revoked and accounts banned.
